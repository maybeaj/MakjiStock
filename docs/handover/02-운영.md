# 막지스톡 인계 — 운영

> 2026-10-07 기준. "이런 일이 생기면 무엇을 어디서 하나"를 상황별로 적었습니다. 대부분은 어드민(`/admin`)에서 코드 없이 합니다. 코드 배포가 필요한 상황은 표시해 두었습니다. 자동 작업의 세부 운영은 [가격 자동화 실행 가이드](../가격자동화-실행가이드.md)를 따릅니다.

## 매일 확인할 것

어드민 `/admin/products` 상단 카드 네 개만 보면 됩니다.

| 카드 | 정상 | 이상하면 |
|---|---|---|
| 판매 중 | 판매 중인 빵 수 | 의도와 다르면 상품 목록의 "판매" 칸 확인 |
| 오늘 오전가 반영 | 06:30 이후 `n / n` | 일부만 반영 → 아래 [자동 작업이 실패했을 때](#자동-작업이-실패했을-때) |
| 다음 가격 계산 | 15:00 오후가 또는 05:30 오전가 | — |
| 확인 필요 | 0건 | 오늘 계산이 일부 실패·보류됨 → 아래 절 |

주간 성과는 `/admin/kpi`에서 봅니다. **지금 주문·코드 수치는 데모몰 기준**이라 실제 매출이 아닙니다.

## 빵을 추가할 때

1. `/admin/products` → **빵 추가**.
2. 화면 이름, 티커(영문 3자, 나중에 못 바꿈), 상세 이름(몰 상품명과 같게), 정가(10원 단위), 네이버 검색어(한 줄에 하나, 최대 20개), 사진(JPG·PNG·WEBP, 4MB 이하)을 넣습니다.
3. Cafe24 상품번호를 넣고 **연결 확인**으로 몰 상품명과 판매가가 맞는지 봅니다. 비워 두면 그 빵은 몰 가격 반영과 쿠폰 발급에서 빠집니다.
4. 실제 몰로 운영 중이면 **자사몰 주소**(makji.kr 상품 상세 주소)를 넣습니다. 비우면 구매 버튼이 몰 첫 화면으로 갑니다.
5. 저장합니다. 목록에 **"첫 가격 대기"** 로 보입니다. 다음 가격 계산(05:30 또는 15:00)이 끝나면 손님 화면에 나타납니다.
6. **몰 상품에 옵션이 있으면 (코드 배포 필요)**: 옵션별 정가를 `config/cafe24-option-prices.ts`에 개발자가 추가해야 옵션가에도 같은 할인이 들어갑니다.

검색어 고르는 기준은 [막지 상품 검색어](../막지-상품6종-검색어.md)에 있습니다. 추가 내역은 `/admin/audit`에 자동으로 남습니다.

## 빵 정보를 바꾸거나 판매를 멈출 때

`/admin/products` → 해당 빵 **수정**. 모두 다음 가격 계산부터 반영되고, 이미 나온 가격은 그대로입니다.

| 바꾸는 것 | 주의 |
|---|---|
| 정가 | 몰에 옵션이 있는 빵이면 `config/cafe24-option-prices.ts`의 옵션 정가도 개발자가 같이 고쳐야 합니다 (코드 배포 필요) |
| 검색어 | 바꾸면 검색지수가 새 검색어 묶음으로 다시 계산돼, 전날과 비교가 한 번 튈 수 있습니다 |
| 사진·화면 이름·상세 이름 | 바로 반영 |
| 판매 끄기 | 다음 가격 계산부터 빠지고 손님 목록에서 사라집니다. 이미 받은 잠금·쿠폰은 그대로 유효합니다 |
| 티커 | 바꿀 수 없습니다 (잠금·구매 링크가 티커로 이어져 있음) |

## 할인율·쿠폰 보상률을 바꿀 때

`/admin/pricing`에서 합니다. 코드나 `config/pricing-products.json`을 고쳐도 운영 가격은 바뀌지 않습니다.

1. 값을 고치면 **저장 전 검사**가 바로 결과를 보여줍니다. 하나라도 실패하면 저장할 수 없습니다 (주문당 최대 할인 38%, 안정형 최대 < 공격형 최대 등).
2. **백테스트 실행**으로 지난 90일을 새 값과 지금 값으로 다시 계산해 비교합니다 (평균 할인, 상한에 닿은 장, 정가로 멈춘 장, 최대 변동).
3. 변경 이유를 적고 **저장**합니다. 새 버전(v1.4 → v1.5)이 만들어지고 다음 가격 계산과 새로 받는 쿠폰부터 적용됩니다.
4. 저장한 버전은 지울 수 없습니다. **되돌리려면 이전 값으로 다시 새 버전을 저장**합니다.

숫자의 의미와 근거는 [산식과 쿠폰 공부노트](../산식과-쿠폰-공부노트.md), 버전 이력은 [산식 버전](../산식-버전.md)에 있습니다.

## 특정 회차에 이벤트 보상률을 걸 때 (코드 배포 필요)

"9/30 오전장은 안정형 10% 고정" 같은 이벤트는 어드민에 없습니다. 개발자가 `lib/bread-market/reward-policy.ts`의 `INSTANT_REWARD_OVERRIDES`에 `"YYYY-MM-DD-am@am": 10` 형식으로 한 줄 넣고 배포합니다. 그 회차가 지나면 지워도 됩니다. 이 값도 주문당 38% 천장은 넘지 못합니다.

## 자동 작업이 실패했을 때

| 증상 | 원인 | 할 일 |
|---|---|---|
| 06:00이 지났는데 오전가가 일부만 나옴 | 네이버 검색지수가 늦게 올라와 그 빵을 보류함 | 대부분 저절로 해결됩니다. 06:00~10:00 매시 보류된 빵만 다시 계산합니다 |
| 10시가 지나도 그대로 | 검색지수·환율 API 오류 | Supabase `job_runs`에서 오늘 행의 `error_message` 확인 → [실행 가이드](../가격자동화-실행가이드.md#수동-실행)대로 수동 실행 |
| 가격은 나왔는데 몰 가격이 그대로 | Cafe24 반영 실패 (`daily_prices.cafe24_apply_status = failed`) | 자동 재시도는 없습니다. Cafe24 토큰부터 확인 (아래) |
| 가격 계산이 503 으로 멈춤 | 운영 산식(`pricing_versions`)을 못 읽음 | Supabase 상태 확인. DB 를 못 읽으면 일부러 계산을 멈춥니다 |
| 손님이 안정형 쿠폰을 못 받음 ("발급할 수 없어요") | 같은 이유 (503) | 같음 |

## Cafe24 연결이 끊겼을 때

앱 등록·권한·환경변수까지 포함한 전체 절차는 [04-Cafe24-연결.md](04-Cafe24-연결.md)에 있습니다.

- 상태 확인: `node scripts/cafe24-token.mjs` (로컬에서, 운영 DB 환경변수로)
- 다시 연결: 배포 주소의 `/api/auth/cafe24/start`를 열고 몰 관리자로 동의합니다. 토큰은 DB 에 암호화돼 저장되고 서버가 알아서 갱신합니다.

## 실제 몰(makji.kr)로 옮길 때

[실행 가이드의 "연결 몰" 절](../가격자동화-실행가이드.md#연결-몰-지금은-데모몰)을 순서대로 따릅니다. 핵심은 **`CAFE24_MALL_ID`와 `SHOP_TARGET=live`를 함께 바꾸는 것**입니다. 하나만 바꾸면 손님은 makji.kr 로 가는데 할인코드는 데모몰에 생겨 "없는 코드"로 거절됩니다.

makji.kr 주문서에는 할인코드 입력란이 이미 있습니다(Cafe24 기본 스킨). 손님은 비회원으로도 코드를 쓸 수 있습니다.

## DB 를 바꿀 때 (개발)

1. `supabase/migrations/`에 다음 번호로 새 파일을 만듭니다 (예: `012_….sql`). 기존 파일은 고치지 않습니다.
2. `npm run db:setup-sql`로 새 DB 세팅 파일을 다시 만듭니다 (잊으면 테스트가 실패합니다).
3. **운영 Supabase SQL Editor 에서 새 파일을 먼저 실행**하고, 그다음에 코드를 푸시합니다. 순서가 바뀌면 배포된 코드가 없는 컬럼을 읽어 화면이 깨집니다.

## 새 환경을 처음 세팅할 때

1. Supabase 새 프로젝트 → SQL Editor 에서 `supabase/setup.sql` 실행 (Storage 가 켜져 있어야 사진 버킷이 생깁니다).
2. Vercel 환경변수를 [`.env.example`](../../.env.example) 기준으로 채웁니다. `ADMIN_PASSWORD`, `CRON_SECRET`, 암호화 키 두 개는 새로 만듭니다 (`openssl rand -hex 32`).
3. Cafe24 개발자센터 앱을 준비하고([04-Cafe24-연결.md](04-Cafe24-연결.md) 3~4절), 배포 후 `/api/auth/cafe24/start`로 몰을 연결하고, `/admin/products`에서 상품번호를 넣고 연결 확인을 합니다.
4. 가격 계산을 드라이런으로 한 번 돌려 봅니다 ([실행 가이드](../가격자동화-실행가이드.md#수동-실행)).

## 어드민 비밀번호를 바꿀 때

Vercel 환경변수 `ADMIN_PASSWORD`를 바꾸고 다시 배포합니다. 비워 두면 어드민이 아무에게도 열리지 않습니다.
