# 가격 자동화 실행 가이드

> 산식 부분은 v1.0 이전 기록이다. 현재 산식(v1.2)은 검색 ×0.15(최대 15%), 환율 하락 ×14(최대 +28%p)·상승 ×7(최대 −14%p), 상품 할인 합계 0~28%이고 정가를 넘지 않는다. 쿠폰과 합친 주문당 상한은 38%다. 기준은 [할인율 결정 리포트](할인율-결정-리포트.md)와 `config/pricing-products.json`이다. 실행 절차(ECOS·Cafe24·시뮬레이션 명령)는 그대로 유효하다.

## 결론

소비자는 로그인하지 않아도 된다. 네이버 DataLab과 환율 API, Cafe24 Admin API 호출은 모두 Next.js 서버 또는 예약 작업에서만 실행한다. Cafe24의 Bearer 토큰은 쇼핑객 토큰이 아니라 쇼핑몰 운영자 앱의 OAuth 토큰이다.

## 현재 산식

```text
검색쿠폰(%p) = 검색지수 × 0.10
환율원시조정(%p) = 환율하락률(%) × 0.28 × 50
환율조정(%p) = clamp(환율원시조정, -28, +28)
할인율(%p) = min(38, 검색쿠폰 + 환율조정)

원시가격 = 기준가 × (1 - 할인율 / 100)
공개가격 = round(원시가격 / 10) × 10
화면 등락률 = (현재 공개가격 / 직전 확정가격 - 1) × 100
```

공개가격은 10원 단위로 반올림한다. 동일한 금액을 Supabase와 Cafe24에 저장·전송한다.

산출가에는 일일·전일 대비 변동폭 제한, 상품별 최소 판매가, 마진율·마진 하한을 추가로 적용하지 않는다. 총 할인은 38%에서 제한한다. 환율 조정은 ±28%p에서 제한하고 검색쿠폰은 0~10%p이므로, 이론상 총 할인율 범위는 -28%~38%, 판매가격 범위는 정가의 62%~128%다.

`검색지수`는 상품별 90일 요청 안에서 0~100으로 정규화된 Naver ratio의 절댓값이다. 전일 대비 변화량은 산식에 넣지 않는다. 검색지수가 100이면 검색쿠폰은 10%p다. `환율하락률`은 원/달러 환율이 내리면 양수, 오르면 음수다. 따라서 환율 하락은 할인을 늘리고 환율 상승은 가격을 올린다. 할인율이 음수면 할증이다.

환율 입력은 한국은행 ECOS `731Y003`의 원/달러 일별 시가(`0000002`)와 종가 15:30(`0000003`)를 한 쌍으로 사용한다. 공개일 D의 오전 6시 가격은 D-1까지 확인 가능한 최근 영업일의 시가와 종가를 비교하고, 오후 4시 가격은 그 종가와 D의 시가를 비교한다. D의 시가가 없는 주말·공휴일에는 오후 가격을 새로 계산하지 않고 오전 확정가격을 유지한다.

## 시뮬레이션

프로젝트 밖의 기존 환경 파일을 그대로 지정할 수 있다. 비밀값은 결과 파일에 기록하지 않는다.

```bash
npm run simulate:pricing -- \
  --env-file /Users/maybeaj/workspace/makji2/.env \
  --start 2026-06-18 \
  --end 2026-09-15 \
  --naver-provider hub \
  --fx-source ecos
```

반복 실행과 운영 환경의 `.env`에는 `BOK_ECOS_API_KEY`가 필요하다. 로컬 검증은 ECOS의 공식 `sample` 키로도 실행할 수 있지만 조회량 제한이 있어 운영용으로 사용하지 않는다. 한국수출입은행 매매기준율과 Frankfurter 기준환율은 시가·종가 쌍이 아니므로 가격 산정 입력으로 사용하지 않는다.

결과는 `artifacts/`에 JSON, CSV, Markdown으로 저장된다. JSON은 Cafe24 반영기의 입력이고 CSV는 차트/스프레드시트 분석용이다.

가중치 후보를 비교할 때도 할인·할증 범위와 평균 할인율을 함께 확인한다.

```bash
npm run simulate:pricing -- \
  --env-file /Users/maybeaj/workspace/makji2/.env \
  --start 2026-06-18 \
  --end 2026-09-15 \
  --naver-provider hub \
  --fx-source ecos \
  --search-weight 0.1 \
  --fx-weight 0.28 \
  --fx-scale 50 \
  --fx-discount-cap 28 \
  --fx-surcharge-cap 28 \
  --output artifacts/stable
```

## Cafe24 드라이런과 반영

먼저 `.env`의 상품번호 매핑을 채운다. 기본 실행은 외부 변경이 없는 드라이런이다.

```bash
npm run cafe24:prices -- --input artifacts/pricing-simulation-YYYY-MM-DD-YYYY-MM-DD.json
```

확인 뒤 실제 반영할 때만 `--commit`을 붙인다.

```bash
npm run cafe24:prices -- \
  --input artifacts/pricing-simulation-YYYY-MM-DD-YYYY-MM-DD.json \
  --commit
```

Cafe24 쇼핑몰의 상품 가격 계산 기준이 공급가 기준이면 `price` 대신 `price_excluding_tax`를 수정해야 할 수 있다. 그 경우 `--price-field price_excluding_tax`를 쓴다.

## 오전 6시·오후 4시 운영 순서

1. 두 세션 모두 공개일 D-1까지의 네이버 검색 지수를 사용한다.
2. 오전 6시에는 D-1까지의 원/달러 종가 중 최근 두 영업일 값을 선택해 하락률을 계산한다.
3. 오후 4시에는 오전이 끝점으로 쓴 그 종가와 D의 원/달러 시가를 비교한다. 당일 시가가 없으면 오전 확정가격을 유지한다.
4. 데이터 누락 시 0으로 대체하지 않고 해당 세션의 직전 확정가격을 유지한다.
5. 각 세션 가격은 기준가에서 독립적으로 계산한다. 앞 세션 가격에 할인율을 재적용하지 않는다.
6. 동일 날짜·상품·세션 계산은 한 번만 확정하도록 Supabase에 유니크 키를 둔다.
7. 계산값, 입력 지수, 환율, 기존 Cafe24 가격, 반영 결과를 감사 로그로 남긴다.
8. Cafe24 PUT 전 현재 가격을 GET하고, 이미 같으면 건너뛴다.

권장 Supabase 키는 `(product_id, publish_date, price_session, formula_version)`이다. 공개 조회는 RLS가 적용된 확정 가격 테이블만 허용하고, API 키와 Cafe24 토큰은 서버 환경변수에만 둔다.
