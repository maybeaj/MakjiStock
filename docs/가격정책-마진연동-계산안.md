## 2. NAVER 검색 지수를 설명하는 방법

NAVER `ratio`는 절대 검색 횟수가 아니다. 응답의 구간별 결과에서 가장 큰 값을 100으로 둔 상대값이다. 따라서 50이 평균·중립이라는 뜻은 아니고, `ratio/100`으로 얻은 0.5도 자동으로 중립이 되지 않는다.

제안은 같은 상품·같은 검색 조건·**동일 응답 안의 두 날짜**를 비교하는 것이다.

```text
g = 최신 완료일 검색 지수 / 그 전날 검색 지수 - 1
e = 최신 적용 환율 / 비교 기준 환율 - 1
```

예: 검색 지수 40 → 50이면 `g = 50/40-1 = 0.25 = +25%`. 검색 지수가 25% 증가했다는 의미이며, 판매량이 25% 늘었다는 뜻은 아니다.

서로 다른 날짜에 조회한 API 응답의 ratio를 그대로 이어 붙이면 조회 기간 변경에 따른 재정규화가 섞일 수 있다. 같은 응답에서 비교값을 계산하고, 그날 확정한 가격·입력·정책 버전을 저장한다. 기존 수집기는 상품별로 따로 조회하므로, 상품 A의 80과 상품 B의 60만 보고 A가 더 많이 검색됐다고 판단하면 안 된다.

0인 분모·날짜 누락·비정상 응답은 0% 변화로 바꾸지 않고 해당 상품의 신규 산정을 보류한다. 환율은 갱신 시각과 영업일 처리 기준을 고정한다. 휴일에는 직전 유효값을 유지하되 같은 환율 충격을 매일 신규 변화로 재적용하지 않는다.

API의 시간 단위는 일·주·월이다. 일 단위 데이터를 사용하는 화면에는 일별 확정 시세를 표시한다. 실제로 수집하지 않은 분봉·체결량은 실제 시장 기록처럼 표시하지 않는다.

출처: [NAVER 통합 검색어 트렌드 공식 문서](https://developers.naver.com/docs/serviceapi/datalab/search/search.md), [로컬 상품별 수집 코드](/Users/maybeaj/workspace/makji/scripts/fetch_keyword_trends.py:72).

## 3. 검색·환율을 정가 기준 등락률로 합산

모든 비율은 소수로 입력한다. 2%는 0.02, 0.5%는 0.005다. `clip(x,a,b)`는 x를 a 이상 b 이하로 제한한다.

그래프의 기준선이 정가라면 정가를 `0%`로 두어야 한다. 따라서 기본값을 항상 할인으로 만드는 `기본 할인 2%`는 그래프용 가격 계산에서 제거한다. 필요하면 별도의 쿠폰 정책으로 운영한다.

```text
검색 기여 T = clip(-a × g, -t, +t)
환율 기여 F = clip(b × e, -f, +f)
원시 등락률 r = T + F + regimeBias
원시 가격 Praw = 정가 P0 × (1+r)
```

여기서 `r=0`이면 정가, `r>0`이면 정가보다 상승, `r<0`이면 정가보다 하락이다. 검색 관심이 늘면 가격을 낮추는 프로모션 방향을 유지하기 위해 검색 변화율에는 음의 계수를 사용한다. `regimeBias`는 특별한 행사나 시장 분위기를 표현할 때만 쓰고, 일반적인 주식형 그래프에서는 `0`으로 둔다.

가상 초기 설정:

| 설정 | 예시 | 의미 |
| --- | --- | --- |
| a | 0.10 | 검색 지수 +10% → 가격 조정 -1%p(할인 +1%p) |
| t | 5% | 검색으로 할인율을 조정할 수 있는 최대 폭 |
| b | 3 | 환율 +0.5% → 할인율 -1.5%p |
| f | 3% | 환율 반영의 최대 폭 |
| regimeBias | 0% | 정가 기준선을 이동시키지 않는 기본값 |

예: 정가 3,800원, 검색 40 → 50, 환율 +0.5%이면 `r = -2.5% + 1.5% = -1%`, 원시 가격은 3,762원이다. 마진 범위 내라면 10원 단위 최종 가격은 3,760원이며 정가 대비 `-1.05%`다. 검색 변화가 -40%이고 환율이 +0.5%라면 `r = +4.0% + 1.5% = +5.5%`가 되어 정가 위로 올라간다.

`r > 0`이면 정가보다 비싸지고, `r < 0`이면 정가보다 싸진다. 정가선과의 차이는 그래프 위치에만 사용한다. 가격 카드의 핵심 표시는 전일 대비 등락률이다. 환율 ×3은 실제 원가 상승의 추정치가 아니라 예시 계수다. 원가에 환율을 따로 반영하는 모델로 바꿀 때에는 같은 효과를 중복 반영하지 않도록 재설계한다.

## 4. 상품 마진으로 최저가 계산

단순 모형에서 마진율은 `(판매가-상품당 비용)/판매가`로 정의한다. 원가 대비 이익률인 마크업과 다르다. 기업 전체 영업이익률을 개별 상품의 마진율로 대입하지 않는다.

기호:
- P0: 상품 정가
- m0: 정가 판매 시 해당 상품의 마진율
- mMin: 할인 후에도 확보할 최소 마진율
- C: 동일한 비용 범위로 계산한 상품당 비용

```text
C = P0 × (1-m0)
마진 최저가 Lmargin = C / (1-mMin)
마진상 최대 할인율 Dmargin = 1-Lmargin/P0
                         = (m0-mMin)/(1-mMin)
```

예: 정가 10,000원, 정가 마진율 30%, 최소 마진율 20%이면 C=7,000원, 최저가=8,750원, 최대 할인율=12.5%다. **30%-20%=10%를 최대 할인율로 쓰면 분모가 달라 정확하지 않다.**

최소 마진율 20%를 동일하게 적용한 비교:

| 정가 마진율 m0 | 마진상 최대 할인율 |
| --- | --- |
| 25% | 6.25% |
| 30% | 12.50% |
| 40% | 25.00% |

기업이 마진을 공개하지 않으면 상품별 **쿠폰 포함 최저 실결제가**를 받아 동일한 최저가 제한에 직접 사용한다. 둘 다 없으면 가상 마진으로 시뮬레이션은 가능하지만 실제 이익 보호가 검증된 가격이라고 할 수 없다.

## 5. 상한·쿠폰·반올림까지 적용

### 상한은 마진만으로 정해지지 않는다

최소 마진은 가격의 하한을 만든다. 가격이 오르면 이 모형의 마진도 커지므로 **최소 마진율만으로 최고가는 계산할 수 없다.**

```text
상한 U = 기업 허용 최고가 또는 P0 × (1+기업 허용 인상률)
하한 L = max(Lmargin, 기업 지정 최저가, P0 × (1-0.38))
```

지정하지 않은 선택 항목은 생략한다. 정가 초과를 허용하지 않으면 U=P0. 양방향 예시 시뮬레이션에서는 허용 인상률 3%를 가정할 수 있다. 이는 기업 확정값이 아니다.

기업이 별도로 최대 마진율 mMax까지 가격 정책으로 정한다면 `U = min(기존 U, C/(1-mMax))`도 가능하다. 이 선택 규칙은 최소 마진 보장의 필수 구성요소가 아니며 비용 모형이 동일해야 한다.

### 쿠폰과 수수료가 있으면 실결제 기준으로 하한 계산

단순 모형에서는 판매가에 따라 달라지는 수수료를 C에 고정 비용처럼 포함하면 안 된다. 다음 확장형을 쓴다.

- C: 판매가와 무관한 상품당 비용
- q: 실결제액에 비례하는 수수료율
- k: 기업이 부담하는 정률 쿠폰 비율
- c: 정률 쿠폰 적용 후 차감하는 기업 부담 정액 쿠폰
- R: 실제 매출로 인식하는 결제액. 세금·배송·플랫폼 지원금은 기업 정산 기준과 맞춘다.

```text
R = P × (1-k) - c
마진율 = ((1-q) × R-C) / R
필요 실결제액 Rmin = C / (1-q-mMin)
표시가격 하한 Lmargin = (Rmin+c)/(1-k)
```

필수 조건은 `q+mMin < 1`, `0 ≤ k < 1`. 쿠폰 적용 순서·최대 할인액·중복 조건이 다르면 실제 정산식을 사용한다. m0가 이미 q를 차감한 동일 정의의 정가 마진이라면 `C=P0×(1-q-m0)`로 역산한다. 수수료가 없는 단순 모형과 혼용하지 않는다.

### 반올림 후에도 한도 준수

```text
L10 = 10 × ceil(L/10)
U10 = 10 × floor(U/10)
최종 가격 P = clip(10 × round(Praw/10), L10, U10)
정책상 최대 할인율 = 38%
실제 정가 대비 할인율(분석용) = 1-P/P0
전일 대비 등락률(화면 표시) = P/Pprev - 1
```

`Pprev`는 전날 확정 가격이다. 전날 가격이 없거나 미갱신이면 등락률을 0%로 임의 처리하지 않고 `-`로 표시한다. 38% 상한만 적용하면 가격 하한은 `P0 × 0.62`이며, 마진 하한이 더 높을 때는 마진 하한을 사용한다.

```text
L = max(P0 × 0.62, Lmargin)
실제 적용 최대 할인율 = min(38%, Dmargin, 기업 지정 할인 한도)
```

L10>U10이면 유효한 가격이 없다. 자동으로 한도를 바꾸지 않고 신규 산정을 보류한다. 기존 가격도 새로운 비용 조건에서 안전한지는 별도로 확인한다. 실제 구현은 십진수 또는 정수 금액 연산으로 경계 오차를 방지한다.

## 6. 10개 중 정가 초과를 최대 3개로 제한

정가를 기준선으로 쓰면 검색·환율 조합의 부호에 따라 상승과 하락이 자연스럽게 모두 나온다. 다만 데이터가 한 방향으로 몰린 날에는 10개가 모두 같은 방향이 될 수 있으므로, “정가 초과 상품은 최대 3개”라는 별도 표시 정책을 둔다.

제안은 **최대 K개 허용**, 예시 K=3이다.

1. 각 상품의 검색·환율·마진·기업 한도를 적용하고 10원 단위 후보 가격을 계산한다.
2. 후보 가격이 정가를 초과하는 상품을 정가 대비 인상률 순으로 정렬한다. 동률은 고정 상품 ID로 결정한다.
3. 상위 K개만 정가 초과를 허용한다.
4. 나머지 초과 상품은 정가로 제한한다. 단, 정가가 해당 상품의 유효한 마진·반올림 구간 안에 있어야 한다.
5. 정가로 낮출 수 없는 상품은 마진과 개수 조건이 충돌하므로 신규 산정을 보류한다. 예시 상품의 정가는 모두 10원 배수다.

이 방식은 “최대 3개”를 보장하며, 입력에 따라 0~3개가 된다. 매일 반드시 2개 또는 3개를 만들려면 모든 신호가 할인 방향인 날에도 일부를 올리는 별도 순위 정책이 필요하다. 이는 데이터에 따른 인상과 구분하여 설명해야 한다. 데모에서는 가상 입력 시나리오를 선택해 2개 또는 3개 상승을 보여줄 수 있다.

아래는 실제 NAVER 데이터가 아닌 계산 검증용 가상 입력이다. 모든 상품 m0=60%, mMin=20%, 쿠폰·수수료 없음, 최대 할인 38%, 인상 한도 3%, `regimeBias=0`, a=0.1, 검색 한도 5%, 환율 +0.5%, 환율 계수 3, K=3을 적용했다. 이 예시는 정가 기준선 위 3개, 아래 6개, 정가 1개가 되도록 입력한 시나리오다. 화면에는 아래 표의 정가 대비 값이 아니라 전날 가격을 이용한 등락률을 표시한다.

## 7. 주식형 대시보드의 표시 기준

- 큰 현재가: 최종 확정 판매가격 P.
- 빨강·파랑 등락: `(오늘 P/어제 P-1)×100%`.
- 별도 정가 할인 배지: `(1-P/P0)×100%`.
- 정가 기준선과 상품별 허용 최저가·최고가를 차트에 표시.
- “가격 산출 근거”에서 기본 할인, 검색 기여, 환율 차감, 마진 제한, 인상 개수 제한을 설명.
- 입력 기준일·가격 확정 시각·미갱신 상태를 표시하고 날짜별 확정 가격을 저장.

정가 10,000원인 상품이 어제 9,000원, 오늘 9,300원이면 그래프에서는 정가선 아래지만 가격 카드에는 **전일 대비 `+3.33%`**를 표시한다. 정가 대비 할인율 7%는 보조 정보로만 둔다. 정가 초과 개수와 전일 대비 상승 개수를 섞어 표시하지 않는다.

기업 자료를 나중에 받으면 상품별 P0, 동일 정의의 m0 또는 C, mMin 또는 최저 실결제가, 최고가/인상 허용률, 쿠폰 부담·수수료 조건을 교체하고 같은 식으로 재계산한다.
