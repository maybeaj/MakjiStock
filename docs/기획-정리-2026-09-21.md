## 2. 변경 — 이번 회차에 정한 것

### 2.1 주말에는 가격 잠금을 받지 않는다

주말은 외환시장이 쉬어 **당일 시가가 없다.** 오후가 크론이 오후가를 만들지 않으므로
(`fx_unavailable` 보류) 잠금가와 비교할 값도, 차액 쿠폰도 없다.

실데이터 3개월:

| | 오전 잠금 기회 | 오후가 없음 | 보상 발생 | 보상 시 평균 차액 |
|---|---|---|---|---|
| 평일 | 390건 | 0건 | 204건 (52.3%) | 593원 |
| 주말 | 156건 | **156건 (전부)** | **0건 (0.0%)** | — |

전체 잠금 기회의 28.6%가 보상 확률 0인 채로 열려 있었다. 하루 한 번뿐인 잠금을
확정적으로 버리게 되므로 닫는다. 공휴일도 같은 이유지만 휴장일 달력이 없어 못 가린다.

### 2.2 예측 할인코드는 발급 시각 + 24시간

기존은 "판정한 시장일의 오후장 끝(다음 날 01:59)"이었다. 기준을 **발급 시각**으로
옮긴다. 크론이 밀렸다가 뒤늦게 따라잡아도 이미 지나간 만료 시각이 붙지 않는다.

잠금 쿠폰은 그대로다 — 보호 구간(16:00~다음 날 01:59)이 곧 유효 기간이다.

### 2.3 그날 가격이 없으면 정가로 보여주고 등락률을 감춘다

새 화면 상태를 하나 추가한다.

| 상태 | 언제 | 가격 | 등락률 |
|---|---|---|---|
| 정가 시간 | 02:00–05:59 | 정가 | 감춤 |
| **가격 준비 중** | 그날 확정가가 아직 없을 때 | 정가 | **감춤** |
| 오전장 / 오후장 | 확정가 있음 | 확정가 | 표시 |

몰은 02:00 에 정가로 되돌아가고 그날 가격이 만들어져야 할인가가 다시 올라간다.
그 사이 전날 가격을 이월하면 **몰은 정가로 결제받는데 화면만 싼 값**을 말한다.

등락률까지 감추는 이유는 따로다. 정가 복귀는 "얼마에서 얼마로 움직였다"가 아니라
"아직 오늘 가격이 없다"는 뜻인데, 퍼센트를 붙이면 **가격 인상으로 읽힌다.**
2026-09-21 오전에 실제로 `▲ +8.7%` 가 세 시간 넘게 떠 있었다.

### 2.4 검색지수가 이월이면 가격을 만들지 않는다

네이버 D-1 검색지수가 없으면 직전 관측치를 이월해 계산하던 것을 **보류로 바꾼다.**
이월값으로 계산하면 전날과 입력이 같아 전날과 같은 가격이 나오고, 화면에는
"새 가격 0%" 처럼 보인다. 그건 거짓말이다.

보류하면 그날 오전가가 영영 안 생기므로 **06·07·08·09·10시(KST)에 따라잡기**를 돈다.
이미 만든 상품은 건너뛴다 — 공개된 가격을 나중 실행이 덮어쓰면 화면에 떴던 값과
달라진다. 늦어도 11:00 전에는 채워진다.

### 2.5 MY 는 지금 할 게 남은 것만 보여준다

결과를 기다리는 예측과 아직 쓸 수 있는 할인코드만 남긴다. 유효기간이 지난 코드는
서버가 코드를 비워 내려보내고 그 줄은 화면에서 통째로 빠진다. 미적중처럼 받을 게
없는 기록도 같이 빠지고, 다 지나가면 빈 상태로 돌아간다.

지난 적중을 붙들고 있을 이유가 없고, 죽은 번호를 복사하면 결제 직전에야 안다.

### 2.6 마켓 예측 카드는 지금 열린 회차만 말한다

기존 배지는 회차와 무관하게 **가장 최근 제출 한 건**의 결과였다. 어제 적중한 배지가
오늘도 붙어 있었고, 카드 본문의 빵(오늘의 추천)과 배지의 빵이 서로 다른 빵이었다.

지금 열린 회차에 참여했는지만 본다. 참여했으면 본문도 내가 고른 빵과 기준가로 바꾼다.
결과는 MY 에 있다.

### 2.7 운영 원칙 — 공개된 확정가는 바꾸지 않는다

확정가는 한 번 공개하면 그 장이 끝날 때까지 고정이다. 잠금과 예측이 전부 그 전제
위에 서 있다. 잘못 나간 날은 되돌리는 게 아니라 다음 장부터 바로잡는다.

2026-09-20 에 한 번 어겼고 **그 대가가 다음 날 실현됐다.** 예측 기준가를
19,870 → 20,130 으로 옮겼는데 09-21 오전가가 20,020원으로 그 사이에 들어와
승자가 그대로 뒤집혔다. 경위와 조건은 [도착 시각 문서](네이버-검색지수-도착시각.md)에 있다.

**남의 예측이 걸려 있으면 하지 않는다.**

### 2.8 로컬·프리뷰는 실몰에 쓰지 않는다

`.env` 와 `.env.local` 이 같은 Cafe24 몰(rabbit3456)을 가리킨다. DB 는 갈라져 있는데
쿠폰과 상품 판매가는 운영과 같은 곳에 쌓이고 있었다.

GET 은 통과시키고 쓰기만 막는다. 쿠폰은 던지지 않고 코드 문자열만 만들어 DB 에
남기므로 판정·화면은 운영과 같은 경로로 흐른다. 연동 자체를 확인해야 할 때만
`CAFE24_ALLOW_LOCAL_WRITES=1` 로 연다.

## 3. 관측 — 실데이터로 확인한 것

### 3.1 네이버 검색지수는 오전 8~9시대에 올라온다

| 잰 날짜 | D-1 | 마지막 미도착 | 첫 도착 |
|---|---|---|---|
| 2026-09-20 | 2026-09-19 | 05:21 (운영 크론) | 09:30 (수동) |
| 2026-09-21 | 2026-09-20 | 08:16 (운영 크론) | 09:09 (probe) |

겹치는 구간은 **08:16~09:09**. 문서에 갱신 시각이 명시된 것을 못 찾아 API 를 직접
찔러 쟀다. 당일 데이터는 오지 않고 D-1 까지만 오며, 없는 날짜는 0 이 아니라
배열에서 빠진다.

**05:30 본 실행은 아직 한 번도 성공한 적이 없다.** 09-21 에는 05:30·06·07·08시
네 회차가 모두 보류돼 오전장 내내(06:00~09:49) 화면이 정가였다.

### 3.2 "틀리지만 않으면 5%" 의 실제 확률은 52.1%

운영 546쌍(기준가=오전가 → 다음 날 오전가):

```
올랐다 256 (46.9%)   내렸다 267 (48.9%)   같다 23 (4.2%)
→ 방향을 동전 던지듯 찍어도 보상 확률 52.1%
```

무승부 4.2%가 덤이라 **절반 넘게 쿠폰이 나간다.** "틀리지만 않으면"이라는 문구는
관대한 예외처럼 들리지만 실제로는 동전 던지기 + 4%p 다. 의도한 수치인지 확인이 필요하다.

## 4. 미결정 — 다음 회차로 넘긴다

### 4.1 오전장 공개 시각 06:00 을 유지할 것인가

3.1 대로면 **매일 아침 세 시간 남짓은 정가**다. Hobby 는 크론을 분 단위로 당길 수
없어 따라잡기 말고는 손쓸 방법이 없다. 선택지:

1. 공개 시각을 늦춘다 — 잠금 가능 구간(06:00–15:59)과 예측 판정 시각이 함께 움직인다
2. **정가 리셋(02:00)을 가격 산정 직전으로 옮긴다** — 정가 구간이 줄어 전날 가격
   이월이 다시 맞는 답이 된다. 2.3 의 전제가 바뀌므로 함께 검토해야 한다
3. 그대로 두고 "가격 준비 중" 상태로 버틴다

며칠 더 재고 정한다. `npm run probe:naver` · `node scripts/naver-lag-probe.mjs --summary`

### 4.2 잠금 쿠폰이 예측 쿠폰을 가린다

한 주문에 코드 하나만 쓴다.

```
잠금 차액 쿠폰   평일 52.3% 발생, 평균 593원
예측 5% 쿠폰     모닝롤 기준 220원
```

잠금이 대체로 2~3배 크다. 하루에 잠금 1회 + 예측 1회를 다 하게 만들어놨는데 보상은
하나만 쓰이니 **예측의 유인이 약하다.** 화면은 "여러 개라면 금액이 큰 코드를 쓰세요"
로 처리하고 있는데, 이건 설명이지 해결이 아니다.

### 4.3 주말 비대칭을 어떻게 설명할 것인가

잠금은 주말에 닫고 예측은 그대로 받는다. 예측은 판정이 다음 날 **오전가**고 주말에도
오전가는 나오므로 논리는 맞다. 다만 사용자에게는 "토요일엔 예측은 되고 잠금은
안 된다"가 설명이 필요한 상태다.

### 4.4 잠금 카드가 없는 쿠폰을 약속한다

`MarketPanel` 의 잠금 카드는 **가격만 비교하고 실제 발급 여부를 보지 않는다.**
보호 구간에 현재가가 잠금가보다 높으면 "차액 쿠폰 N원"이라고 쓰는데, 크론이
보류·실패하면 없는 쿠폰을 약속하게 된다. `MyPanel` 은 발급 여부를 제대로 본다.
버그로 처리할지, 문구를 "발급 예정"으로 바꿀지 정해야 한다.
