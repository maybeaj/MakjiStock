# 막지 가격 산정 대상 상품 6종

> 검색어의 정본은 DB `products.keywords` 다. 어드민 `/admin/products` 에서 빵마다 고치고(최대 20개, 줄바꿈·쉼표로 구분, 중복은 하나로 합침), 바꾼 검색어는 변경 기록(`/admin/audit`)에 남는다. 가격 크론은 판매 중(`active`)인 상품의 `keywords` 를 그대로 읽는다.
> 아래 상품 표와 검색어 목록은 처음 정한 6종의 **스냅숏**이다(`config/pricing-products.json` 과 같은 값). 어드민에서 고쳤거나 빵을 추가·멈췄다면 지금 값은 어드민 화면이 맞다.

## 공통 수집 규칙

- 네이버 통합 검색어 트렌드 API는 상품마다 독립적으로 1회 호출한다.
- 하루 수집 횟수는 판매 중인 상품 수만큼이다(6종이면 6회).
- 각 상품의 검색어는 하나의 `keywordGroup`으로 묶는다.
- 모든 상품은 동일한 조회 시작일과 종료일을 사용한다.
- 상품별 검색지수는 각 요청 안에서 0~100으로 독립 정규화되므로 상품 간 절대 검색량으로 비교하지 않는다.
- 가격 산정에는 공개일 D-2 의 검색지수를 쓴다(`lib/pricing/daily-job.ts` `SEARCH_SIGNAL_LAG_DAYS = 2`). 네이버가 전날 지수를 08~09시대에 올려 오전가 크론 시각에는 D-1 이 없기 때문이다. D-2 값이 없으면 이월하지 않고 그 상품의 가격을 보류한다.

## API 호출 순서

1. MRL 검색 트렌드 호출
2. TTR 검색 트렌드 호출
3. MUF 검색 트렌드 호출
4. SCN 검색 트렌드 호출
5. FNC 검색 트렌드 호출
6. GFD 검색 트렌드 호출

각 요청은 앞 요청의 성공 여부와 응답 시간을 기록한 뒤 다음 상품을 호출한다. 일부 상품의 요청이 실패하면 해당 상품의 가격은 새로 산정하지 않고 직전 확정 가격을 유지한다.

## 운영 전 확인사항

- 여섯 상품의 실제 Cafe24 `product_no`를 입력한다. 지금은 어드민 상품 수정 화면에서 넣고 연결 확인 버튼으로 몰에 있는지 확인한다.
- 상품명과 기준가는 Cafe24 상품 정보와 일치하는지 확인한다.
- GFD 검색어는 네이버 API의 그룹당 최대치인 20개이므로 추가할 때 기존 검색어를 교체해야 한다. 어드민도 20개를 넘으면 저장하지 않는다.
- 품절·판매중지 상품은 API 호출 대상과 가격 반영 대상에서 함께 제외한다. 어드민에서 판매 여부를 끄면(`active = false`) 크론이 그 상품을 읽지 않는다.
