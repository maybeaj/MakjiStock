# 매수가 기준 예측 제외 사유

작성일: 2026-09-19

## 결론

1차 출시에서는 `매수가 기준 예측`, `구매자 7% 보상`, `구매자 미적중 3% 보상`을 제외한다. 화면에는 일반 예측만 남기고, 기준가는 서버가 확정한 오늘 가격으로만 둔다.

## 왜 지금 넣으면 안 되는가

매수가 기준 예측은 “사용자가 얼마에 샀는지”를 서버가 검증해야 성립한다. 현재 앱은 막지 자사몰로 사용자를 보내는 구조이고, 결제는 Cafe24에서 끝난다. 따라서 앱 안의 버튼 클릭만으로는 실제 구매 여부, 주문 취소 여부, 수량, 결제 단가, 쿠폰 적용 후 실결제가를 확정할 수 없다.

쿠키나 localStorage에 구매가를 저장하는 방식도 불가하다. 사용자가 값을 조작하거나 브라우저 기록을 지우면 기준가가 흔들리고, 보상 지급 근거로 쓸 수 없다. 예측 상태처럼 “참여 여부”는 익명 visitor cookie로 서버가 관리할 수 있지만, “매수가”는 Cafe24 주문 데이터와 연결되어야만 확정값이 된다.

## 구현하려면 필요한 것

- Cafe24 주문 API 또는 주문 웹훅으로 실제 주문을 서버가 확인해야 한다.
- 막지 앱의 구매 이동 기록과 Cafe24 주문을 안정적으로 연결할 `click_id` 또는 회원/주문 인증 흐름이 필요하다.
- 주문 취소, 부분 취소, 수량 변경, 쿠폰 적용 후 결제 단가를 어떻게 기준가로 볼지 정책이 필요하다.
- 검증된 주문 1건당 예측 1회만 허용하는 DB 제약이 필요하다.

## Cafe24 쿠폰 안내 변경

현재 운영 확인 결과, 비회원 주문서에서 할인코드가 바로 적용되지 않는다. 그래서 사용자 안내는 “비회원 주문에도 사용 가능”이 아니라 “막지 자사몰 가입 후 쿠폰번호 등록 필요”로 통일한다.

공식 문서 기준으로도 Cafe24는 `coupon`과 `discount_code`를 별도 할인 수단으로 다루며, 쿠폰 쪽은 회원/고객 단위 발급 구조가 강하다. Admin API에는 할인코드 생성 리소스가 있고 `available_user`의 `A: 전체` 옵션이 있지만, 실제 주문서 적용 가능 여부는 쇼핑몰 설정과 프론트 적용 상태의 영향을 받는다.

참고 근거:

- Cafe24 Admin API `Discountcodes`: `POST /api/v2/admin/discountcodes`, `available_user` 값 `M: 회원`, `A: 전체`
  https://developers.cafe24.com/docs/api/admin/
- Cafe24 쿠폰 설정: 비회원에게 쿠폰을 “노출”하는 `show_coupon_to_non_members` 설정
  https://developers.cafe24.com/docs/en/api/admin/?version=2025-03-01
- Cafe24 고객 쿠폰 조회 API: 고객의 사용 가능 쿠폰은 `member_id` 기준으로 조회
  https://developers.cafe24.com/docs-new/en/docs/admin/get-customers-by-member-id-coupons
- Cafe24 쿠폰 발급/조회 매뉴얼: 발급 대상 회원/조건 선택, 보유 회원 기준 관리
  https://ecsupport.cafe24.com/web/upload/manual/ec/prm/prm1040004.html

## 팀에 전달할 한 문장

매수가 기준 보상은 “구매 버튼을 눌렀다”가 아니라 “Cafe24에서 어떤 주문을 얼마에 실제 결제했다”를 검증해야 하므로, 주문 연동 전에는 일반 예측 3%만 출시한다.
