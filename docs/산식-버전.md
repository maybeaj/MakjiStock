# 산식 버전

`config/pricing-products.json` 의 `formulaVersion` 이 단일 출처입니다.
`daily_prices` 유니크 키에 들어가므로(`product_id, publish_date, price_session, formula_version`),
버전을 올리면 같은 날짜를 다시 계산해도 공개됐던 행을 덮어쓰지 않고 새 행이 생깁니다.

산식을 바꾸면 반드시 올립니다. 안 올리면 "공개된 확정가는 바꾸지 않는다"는 원칙이
조용히 깨집니다 (docs/네이버-검색지수-도착시각.md).

| | v1.3 | v1.4 |
|---|---|---|
| 환율 상승 반영 비율 (`fxRisePassThroughPct`) | 50% (× 7) | **100% (× 14)** |
| 환율 상승 쪽 상한 (`fxSurchargeCapPct`) | −14%p | **−28%p** (하락 쪽 +28%p 와 같게) |

90일 924세션 기준 변화:

- 상품 할인 평균 **12.55% → 11.86%**
- 정가 그대로인 세션 0% → **2.6%** (환율이 오른 날 할인이 0 까지 줄어든 경우. 하한 0 이라 정가를 넘지는 않는다)
- 같은 날 오전↔오후 가격 차이 평균 6.28% → **7.69%**, 오전가 = 오후가 0.3% → 0%

하한 0 을 풀어 할증을 허용하면 같은 90일에 정가 초과 2.6%, 최대 정가 +5.9% 였습니다. 지금은 허용하지 않습니다.

이미 공개된 v1.3 행은 그대로 둡니다.

## v1.3 — 2026-09-27

**상품 할인 상한을 28% → 25%로 낮추고, 쿠폰 금액에 정가의 13% 천장을 걸었습니다.** 가중치와 환율 구간, 쿠폰 보상률 폭은 v1.2 그대로입니다.

| | v1.2 | v1.3 |
|---|---|---|
| 상품 할인 상한 (`discountCapPct`) | 28% | **25%** |
| 판매가 하한 | 정가의 72% | **정가의 75%** |
| 쿠폰 금액 | 판매가 × min(R, 38 − 발급 시점 할인율) | **min(판매가 × R, 정가의 13%)** |

바꾼 이유는 둘입니다.

1. **v1.2는 38%를 보장하지 못했습니다.** 쿠폰은 발급 시점 할인율로만 잘랐는데, 공격형(24시간)·안정형(3시간)은 받은 뒤 오후가가 더 내려간 장에서도 쓰입니다. 오전 할인 0%에 공격형 13%를 받고 오후 할인 28%에 쓰면 40.9%입니다. 90일 백테스트에서는 한 번도 없었지만(최대 36.6%) 막는 장치가 없었습니다.
2. **28%를 두고 38%를 지키려면 공격형을 정가의 10%에서 잘라야 합니다.** 그러면 공격형 최대치가 안정형 최대 10%와 같아져, 모른 채 거는 공격형을 고를 이유가 사라집니다. 25% + 13% = 38%로 맞추면 공격형 13%를 그대로 살립니다.

90일 924세션 기준 비용: 원시 할인이 25%를 넘은 세션 31개(3.4%)가 최대 3%p 덜 할인되고, 상품 할인 평균은 **13.00% → 12.93%** 입니다. 38% 초과는 이론상으로도 0이 되고(최대 38.0%), 공격형 최대 지급은 정가의 10.0% → **12.9%**, 안정형은 9.9%로 그대로입니다.

이미 공개된 v1.2 행은 그대로 둡니다.

## v1.2 — 2026-09-23

**상품 할인 상한을 38% → 28%로 낮췄습니다.** 가중치와 환율 구간은 v1.1 그대로입니다.

| | v1.1 | v1.2 |
|---|---|---|
| 상품 할인 상한 (`discountCapPct`) | 38% | **28%** |
| 판매가 하한 | 정가의 62% | **정가의 72%** |
| 쿠폰과 합친 주문당 상한 (`TOTAL_CAP_PCT`) | 38% | 38% (그대로) |

쿠폰 폭도 같은 날 바꿨습니다. 쿠폰은 산식 버전과 따로 관리하지만(`lib/bread-market/reward-policy.ts`) 두 값이 한 덧셈으로 묶여 있어 함께 적습니다.

| 쿠폰 | 전 | 후 |
|---|---|---|
| 안정형 · 오전장 | 13~15% | **7~10%** |
| 안정형 · 오후장 | 10~12% | **5~7%** |
| 공격형(예측) | 5~20% | **5~13%** |

28% + 오전 안정형 최대 10% = 38%. 안정형은 합계 상한에 잘리지 않고, 공격형 11~13%만
상품 할인이 25%를 넘는 날에 잘립니다.

이미 공개된 v1.1 행은 그대로 둡니다. 이미 제출한 공격형 예측은 저장된 보상률을 씁니다.

## v1.1 — 2026-09-22

**오전장 환율 구간을 전영업일 안으로 좁혔습니다.**

| | v1.0 | v1.1 |
|---|---|---|
| 오전 06:00 | 전전영업일 종가 → 전영업일 종가 | **전영업일 시가 → 전영업일 종가** |
| 오후 16:00 | 전영업일 종가 → 당일 시가 | 그대로 |

v1.0 은 오전장 구간이 전날 오후장과 겹쳤습니다. 같은 환율 움직임이 이틀에 걸쳐
두 번 가격에 반영됐고, 특히 화요일 오전은 주말 사흘치 갭을 통째로 받았는데 그
갭은 이미 월요일 오후장이 받은 것이었습니다.

v1.1 에서는 두 장이 시간을 이어 덮습니다.

```
전영업일 시가 ──[오전장]──> 전영업일 종가 ──[오후장]──> 당일 시가
```

90일 924세션 기준 변화:

- 38% 상한 도달 **11회 → 0회** (주말 갭 중복이 만들던 극단값이 사라짐)
- 오전 환율 변동 |평균| 0.406% · 오후 0.279% — 하루 안의 시가-종가가 오버나이트 갭보다 넓다
- 오전 할인율 평균 13.73% · 오후 11.08%
- 같은 날 오전↔오후 가격 차이 평균 7.5% → 6.5%

전영업일 시가가 없으면 오전 세션을 만들지 않습니다. 주말은 전과 같습니다 —
전영업일 시가는 있고 당일 시가만 없어 오전가는 나오고 오후가는 오전가를 유지합니다.
